## Тестирование веб-приложения

Для проверки стабильной работы веб-приложения «Анализатор статического кода» было проведено комплексное тестирование всех его страниц, пользовательских сценариев и функциональных возможностей. В процессе тестирования особое внимание уделялось корректному отображению результатов анализа, функционированию CRUD-операций с историей анализов, работе линтеров для различных языков программирования, а также удобству взаимодействия пользователя с интерфейсом. Тестирование производилось в браузере Google Chrome.

После открытия сайта пользователь попадает на главную страницу, где отображается информация о проекте, его возможностях и поддерживаемых языках программирования (рисунок 3.1).

Рисунок 3.1 – Главная страница веб-приложения «Анализатор статического кода»

Для доступа к функциональности приложения необходимо пройти регистрацию или войти в систему. Страница регистрации содержит форму с полями для имени пользователя и пароля (рисунок 3.2).

Рисунок 3.2 – Страница регистрации

После успешной регистрации пользователь автоматически входит в систему и перенаправляется на страницу истории анализов. Страница входа позволяет авторизованным пользователям войти в систему (рисунок 3.3).

Рисунок 3.3 – Страница входа в систему

После входа пользователь получает доступ к основным функциям приложения. Страница загрузки ZIP-архива позволяет выбрать файл проекта и указать его название (рисунок 3.4).

Рисунок 3.4 – Страница загрузки ZIP-архива

После загрузки ZIP-архива с проектом начинается процесс анализа. Система извлекает файлы из архива, определяет их языки программирования и запускает соответствующие линтеры. По завершении анализа пользователь перенаправляется на страницу с детальными результатами (рисунок 3.5).

Рисунок 3.5 – Страница с результатами анализа ZIP-архива

На странице результатов анализа отображается сводная информация о найденных проблемах: количество ошибок, предупреждений и информационных сообщений. Таблица с найденными проблемами содержит информацию о файле, строке, уровне серьёзности, коде правила и описании проблемы. Пользователь может фильтровать проблемы по уровню серьёзности с помощью кнопок фильтрации (рисунок 3.6).

Рисунок 3.6 – Фильтрация проблем по уровню серьёзности

На странице результатов также отображается список всех проанализированных файлов с возможностью просмотра их содержимого. При нажатии на кнопку «Просмотр» открывается модальное окно с содержимым файла (рисунок 3.7).

Рисунок 3.7 – Просмотр содержимого файла в модальном окне

Интерактивный анализатор кода позволяет проверять фрагменты кода в реальном времени без загрузки файлов. Пользователь может выбрать язык программирования, вставить код в текстовое поле и получить результаты анализа. При включённом автоматическом анализе результаты обновляются автоматически при изменении кода (рисунок 3.8).

Рисунок 3.8 – Интерактивный анализатор кода

При изменении языка программирования в интерактивном анализаторе автоматически обновляется информация о используемом линтере, а при включённом автоматическом анализе запускается проверка кода (рисунок 3.9).

Рисунок 3.9 – Результаты анализа кода на языке Python

Страница истории анализов отображает все выполненные пользователем анализы с информацией о проекте, статусе, дате создания и действиях. Для каждого анализа доступны кнопки «Подробнее» и «Удалить» (рисунок 3.10).

Рисунок 3.10 – Страница истории анализов

При нажатии на кнопку «Подробнее» открывается страница с детальной информацией об анализе, включая все найденные проблемы и список проанализированных файлов (рисунок 3.11).

Рисунок 3.11 – Страница детальной информации об анализе

При нажатии на кнопку «Удалить» появляется окно подтверждения действия. После подтверждения анализ удаляется из базы данных и исчезает из списка (рисунки 3.12–3.13).

Также было проверено, что система корректно игнорирует служебные файлы macOS (например, файлы из директории __MACOSX) при анализе ZIP-архивов и не включает их в результаты.

В результате проведённого тестирования подтверждена корректная работа всех основных функций веб-приложения «Анализатор статического кода». Проверка пользовательской части показала стабильность интерфейса, корректность отображения результатов анализа, устойчивость CRUD-операций с историей анализов и правильную работу линтеров для различных языков программирования. Все сценарии взаимодействия – от регистрации и входа до анализа кода и управления историей анализов – выполняются без ошибок.
